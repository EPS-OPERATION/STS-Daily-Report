# STS default Project bootstrap

Run explicitly from the repository root after migrations:

```sh
bun run db:seed:sts-default
```

This is an optional development/demo bootstrap. It is not a migration, reset, automatic startup action or permission-grant command. The configured `DATABASE_URL` is used; successful writes commit together in one transaction.

## Rerun and data safety

- Project identity is unique code `STS-001`, not name similarity. Another Project with the same display name is untouched.
- Map resolution prefers the exact Master Site Layout name; otherwise it reuses the current default Map, preserving an administrator's rename. Ambiguous matching/default Maps fail and roll back instead of choosing arbitrarily. There is no new Map identity column solely for bootstrap.
- View identity is Map/key; Facility identity is Project/key. Existing rows preserve names, codes, active state, order, uploaded image and placements. Original bootstrap public-image references can be upgraded to MinIO while retaining View IDs; that upgrade updates image metadata/timestamp once. Other user-managed public references and stored image keys remain unchanged.
- Existing extra product records are retained. This creates the 15 initial definitions, not an enforcement operation that deletes additional Facilities.
- A transaction advisory lock serializes bootstrap reruns; the resolved Project row is also locked to coordinate Map default operations.
- PostgreSQL and MinIO do not share a transaction: failed database writes roll back, then newly uploaded objects are removed only after confirming no View references them. If database reference verification fails, objects are retained to avoid deleting a possibly committed image. Reruns skip stored images.
- There is no approved native 15-Facility coordinate dataset in the cleaned development configuration. Historical legacy migration coordinates are not automatically revived. **Zero markers are fabricated.** Existing native markers remain untouched; output counts configured/unconfigured pairs across the two initial Views (30 possible placements).
- **Zero Zones, legacy marker definitions, polygons, Parts, Activities or Contractors are created.** No users or permission grants are written.
- `db:seed` remains development-user only. `db:backfill-facilities` remains a separate legacy-data migration operation.

Fresh local workflow:

1. `bun run db:migrate`
2. `bun run db:seed`
3. Optionally `bun run db:seed:sts-default`
4. Explicitly grant Site Configuration permission to the chosen account through your authorized administration process.
5. Place Facility markers using Site Configuration; create real Parts/Contractors/Activities as needed.
